# SDPE - Backend API

*[🇧🇷 Leia a versão em Português abaixo](#-sdpe---api-backend-português)*

**SDPE - Academic Extension Projects Disclosure System (Backend)**

This repository contains the backend for the **SDPE** system, a RESTful API developed to **manage, promote, and monitor academic extension projects**. The system provides **role-based access control (RBAC)**, **content management**, and **statistical reports**.

**SDPE** is a RESTful API built to manage the lifecycle of IFPR's academic extension projects. It provides endpoints for secure authentication, user management, project submission, document upload, and statistics generation.

## 🔭 Overview

The backend serves as the core processing unit for the SDPE platform, managing:

* **Authentication and Authorization:** Role-based access control (`ADMIN`, `COORDENADOR`, `PARTICIPANTE`) via JWT.
* **Project Management:** Full CRUD operations for projects, including image and PDF document uploads.
* **Reports:** Generation of statistical data regarding views and enrollments.
* **Security:** Protection against automated spam attacks via Altcha integration.

---

## 🚀 Technologies Used

The project was built using the following core technologies and libraries:

* **Java 21** & **Spring Boot 3.5.4**
* **Security:** Spring Security + [JWT](https://www.jwt.io/) (JSON Web Token) for stateless authentication
* **Database:** MySQL (`mysql-connector-j` driver) with Spring Data JPA and Hibernate
* **API Documentation:** SpringDoc OpenAPI [(Swagger UI)](https://swagger.io/)
* **Anti-Spam Security:** [Altcha](https://altcha.org/) integration
* **Email:** Java Mail Sender (Google SMTP)
* **Utilities:** Lombok, Bean Validation

## ⚙️ Environment Setup

### 1. Configuration File (`application.yaml`)

Main configurations are located in `src/main/resources/application.yaml`. Ensure the database credentials match your local environment:

```yaml
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/sdpe-bd
    username: root   # Adjust to your database user
    password: root   # Adjust to your database password
```

### 2. Environment Variables (Recommended)

For email and security (Altcha) features, set the following environment variables or edit the `application.yaml` file directly (not recommended for production):

* `spring.mail.username`: Your sender email
* `spring.mail.password`: Your email application password
* `altcha.secret-key`: Secret key for Altcha widget validation

## 📖 API Documentation (Swagger)

The API features interactive documentation automatically generated by Swagger. With the server running, access:

### Main Endpoints

| Module   | Method | Route                           | Description                                               |
| -------- | ------ | ------------------------------- | --------------------------------------------------------- |
| Auth     | POST   | `/auth/login`                   | Performs login and returns the JWT Token                  |
| Auth     | POST   | `/auth/registrar`               | Creates a new user account                                |
| Projects | GET    | `/api/projetos`                 | Lists all projects (public)                               |
| Projects | POST   | `/api/projetos`                 | Creates a new project (requires token and coordinator role)|
| Admin    | GET    | `/api/admin/painel-administrativo`| Data for the administrative dashboard                     |

## 🔐 Initial ADMIN User Creation

This section describes **only the process of creating the initial ADMIN user** for the system.  
This user will be responsible for approving other users and performing administrative registrations via the system's interface.

### 1. Install Postman CLI

To execute the registration call via terminal, install the Postman CLI:

```bash
npm install -g postman-cli
```

### 2. Register the ADMIN User via API

Run the command below to create the initial administrator user.

> **Important:**
> Adjust the PDF file path in `arquivo=@"/C:/Users/your_file.pdf"` to an existing file on your machine.

```bash
postman request POST 'http://localhost:8080/auth/registrar' \
  --form 'dados={
    "email":"admin.sistema@ifpr.edu.br",
    "senha":"admin123",
    "perfil":"ADMIN",
    "nome":"Roberto Henrique Lima",
    "dataNascimento":"1975-06-15",
    "cpf":"604.059.350-48",
    "cidade":"Curitiba",
    "estado":"PR",
    "ativo":true,
    "vinculoInstitucional":true
  }' \
  --form 'arquivo=@"/C:/Users/your_file.pdf"'
```

### 3. Manual User Activation in the Database

If the user is created with an inactive status, activate it directly in the database (development environment only):

```sql
UPDATE tb_conta SET ativo = true;
```

### 4. Login with the ADMIN User

After activation, use the credentials below to access the system:

```text
Email: admin.sistema@ifpr.edu.br
Password: admin123
```

### 5. ADMIN User Roles

After the first login, the ADMIN user will be able to:
- Approve registered users in the system
- Register professors, students, and coordinators
- Approve registrations directly through the administrative interface
- Manage system access and permissions
